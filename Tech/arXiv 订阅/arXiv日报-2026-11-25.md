## Agent Evaluation Without Ground Truth: A Null Proportion Perspective（2611.31539）｜cs.AI math.ST stat.AP stat.ME stat.TH｜Brian M. Cho, Michael Lindon, Nathan Kallus

**分类**：cs.AI math.ST stat.AP stat.ME stat.TH　|　**作者**：Brian M. Cho, Michael Lindon, Nathan Kallus　|　**链接**：https://arxiv.org/abs/2611.31539

**问题背景**：Agent 的动作正确性通常靠外部核实的 ground truth 判定——证明是否正确、代码是否编译并通过单测。但当编码 / 科学 agent 被授予端到端自主权（提出干预、跑实验、决定部署与后续排查）之后，"agent 的动作是否真的改善了结果"只能从**含噪、经常无定论**的实验里推断出来。此时沿用 ground truth 标签的评测方式本身就是一个被高估的测量装置。

**方法**：把 agent 质量定义为轨迹上"正确决策"的加权和，用**一串 e-value 作为关于正确性的统计证据**替代 ground truth 标签。框架允许决策之间任意相依、轨迹依赖数据而终止、假设动态生成、质量度量在轨迹结束后才定义；在此基础上构造 agent 质量的**上下界估计量与置信集**，统计保证对 agent 轨迹分布**一致成立**（uniformly），并证明该估计量类具有 instance-wise sharpness。

**主要结果**：摘要未给数值，只给案例研究——用该框架比较 Claude Opus 与 Claude Haiku 在"改进某开源 Python 包运行时长"上的成功率差异（以 e-value 序列作为正确性证据、以置信集作为质量结论）。结论形态从"谁分高"变成"在给定证据下，能否排除 Opus 不比 Haiku 好"。

**与 Reliable Agent·统计推断的关系**：这是今天与用户课题最贴的一篇，也是"Agent 做统计推断时的偏差"的正面写法——**把评测标签的偏差问题，换成证据累积问题**：不去问"哪个 agent 的分数更高"，而是问"现有证据能支持多强的结论"。三点可直接借鉴：① 轨迹中决策可相依、假设可动态生成，说明方法是在为**最不利的 agent 行为模式**做保证；② 质量度量允许事后定义，避开了"先定指标再去凑"的偏差；③ 上下界 + 置信集的报告形式，比"leaderboard 上排第几"更接近可审计的结论。e-value 的组合不变性正是它能处理任意相依决策的原因。

## LUCID: Statistically Grounded Self-Correction for LLM Reasoning Evaluation（2611.31595）｜cs.CL cs.LG stat.ME｜Satiyabooshan Murugaboopathy, Adel Daoud, Connor T. Jerzak

**分类**：cs.CL cs.LG stat.ME　|　**作者**：Satiyabooshan Murugaboopathy, Adel Daoud, Connor T. Jerzak　|　**链接**：https://arxiv.org/abs/2611.31595

**问题背景**：廉价 LLM 评分器被用来批量给思维链逐步打分，但**系统性的逐步评分误差**会污染推理审计与解答排序——分错的人会被当成"不会"，分松的人会被当成"会"。这类误差不是随机噪声，而是有方向的偏好（偏严 / 偏松）。

**方法**：LUCID（Loop for Unbiased Calibration via Inference-time Diagnosis）把**提示词自纠错**与**设计型监督学习（DSL, design-based supervised learning）**配对使用，全程不重训、不碰权重。用一小批专家标注集把评分器的偏差"翻译成白话"（rater bias summary），再让评分器对未见步骤重新打分以对齐预测 soundness 率与专家 soundness 率；由于提示词反馈只是移动判定阈值而不改善类平衡判别力，LUCID 额外加了 pre-/post 检查——已经校准好的评分器直接跳过，无效的修正轮次回滚。最后复用同一批专家标签 + 原始语料评分做 DSL 校准与回归去偏，并对成对标注步骤做 sound-step 转移的 DSL 建模，产出 out-of-fold soundness 概率与**双重稳健（doubly robust）估计量**。

**主要结果**：PRM800K 上 GPT-5-mini **偏严**，对计算、验证、以及靠后 trace 的步骤低估最严重；**一次**修正循环把校准间隙从 **7.8 个百分点压到 0.9 个百分点**（预测率与专家率之差的绝对值）；误报（sound 步被判 unsound）**减半**，unsound 步的错误检出 F1 **提升 32%**。只用 1000 条诊断步骤、或只给"总体间隙"反馈，收益同样保留。跨模型可迁移：把 GPT-5-mini 的偏差画像套到 GLM-5.2 上也能提升其 PRM800K 准确率；在数学、科学、网页、逻辑四类基准上，对"偏严但有能力"的评分器都能收窄校准间隙。DSL 方面：out-of-fold soundness 概率让 best-of-K 选择对齐专家标签；**双重稳健估计量在小预算下优于仅用专家标签的回归拟合**，并把 sound-step 转移误差**削减近三分之二**。

**与 Reliable Agent·统计推断的关系**：方法论上和用户课题几乎同构——**用设计型抽样把"评分器偏差"变成可估计、可去偏的量**。三处值得抄：① 偏差先被"写成白话"再交给模型去修，说明偏差诊断本身要先有可解释的中间表示；② 校准间隙（predicted − expert rate 的绝对差）是比"准确率"更贴近偏差的一号指标，日报里出现的多个 LUCID 式变体都可以用这个量对齐；③ 双重稳健估计器在"专家标注预算很小"时仍可用，这与 agent 评测里"标注预算永远不够"的现实高度匹配。同时它给出一个反直觉的提醒：**提示词反馈只挪阈值、不改判别能力**——如果只盯 F1 不盯类平衡，会误以为"修好了"。

## Auditing the Judge: Human-Derived Bias Discovery, Quantification, and Mitigation in LLM Judges（2611.33065）｜cs.AI cs.LG｜Hamin Koo, Chanjoo Jung, Fangzhao Wu, Jaehyung Kim

**分类**：cs.AI cs.LG　|　**作者**：Hamin Koo, Chanjoo Jung, Fangzhao Wu, Jaehyung Kim　|　**链接**：https://arxiv.org/abs/2611.33065

**问题背景**：LLM-as-a-Judge 已经进入评测与训练管线，但其判断常带**系统性偏差**，与人类偏好相冲突。既有工作的问题在于：依赖事先写好的偏差清单（漏掉没被列出的偏差）、只说"有偏差"却不量化偏差强度（无法知道该不该改、值不值得改）、干预手段昂贵。

**方法**：提出 HUB-J 三件套——**发现**：用"人类与 LLM 判断分歧"的案例自动挖掘可解释的偏差因子；**量化**：用"判断一致"的案例配合受控输入改写，观察模型决策的位移来度量每个偏差因子的强度；**缓解**：轻量、无需训练的回归式缓解——估计每个偏差因子对判断的影响量，并把估计效应从判断中扣除。

**主要结果**：HUB-J 既能挖出已知偏差因子，也能发现新因子；能揭示不同模型对各类偏差的**易感度差异**；缓解策略持续减少"由偏差驱动的判断翻转"（decision flips），且跨模型泛化。摘要未给具体数值。

**与 Reliable Agent·统计推断的关系**：这条线（"评测装置自身的可信度"）今天有三篇互相印证（另见 2611.33012 与 2611.31839）。HUB-J 的价值在于把"裁判有偏"从道德判断变成**可测量的量**：分歧样本用来找原因，一致样本用来估强度——这个"用分歧定位、用一致定标"的分工，可直接迁移到 agent 自评（agent 声称"我做对了"）与人评之间的偏差分解上。而且它与 LUCID 正好构成一对：LUCID 从评分器一侧去偏（模型侧），HUB-J 从人类一侧挖因子（数据侧）。

## PAC-style Bounds on the Conditional Validity of Conformal Predictors（2611.33023）｜cs.LG｜Nicolo Colombo

**分类**：cs.LG　|　**作者**：Nicolo Colombo　|　**链接**：https://arxiv.org/abs/2611.33023

**问题背景**：Conformal prediction set 的保证是**边缘有效**（marginal validity，覆盖率对属性空间取平均），但**局部/条件覆盖率**可能与用户设定的目标 1−α 严重偏离。更关键的是：对一般数据生成分布，**用有限校准数据构造条件有效的预测集是不可能的**。也就是说，任何声称"条件覆盖"的系统，其偏差都必然存在——问题只是多大、能否量化。

**方法**：在**不假设分布**的前提下，导出任意 conformal predictor 的输入条件覆盖率的 **PAC 型概率下界**；基于 Markov 与 Cantelli 不等式，同时适配"校准边缘"与"校准条件"两种设定。另给出一个更紧的、依赖模型的 Cantelli 界，其量是条件覆盖率的**方差**，并用完全非渐近的 Hoeffding 论证说明该方差可由数据估计。

**主要结果**：摘要未给实验数值，核心结论是方法论结论——**条件覆盖率方差**可以当作一个可扩展、有理论动机、用来度量"条件有效性"的实证指标（而非只看平均覆盖率）。

**与 Reliable Agent·统计推断的关系**：这一篇提供了今天最缺的一块：**当有人声称"我的 agent 输出有 90% 保证"时，保证到底覆盖了谁**。边缘保证 + 条件偏差，正是"报告的保证 ≠ 实际的保证"的教科书例子，与用户关心的 bias 同源。若把 conformal 包装套在 agent 的决策、置信声明或工具选择上，PAC 下界与条件覆盖方差是现成的审计量。缺憾：只给下界，不给"如何真正做到条件有效"的构造法——与 2611.32182 的 HPD 构造形成互补。

## Asymptotically Efficient Conformal Inference for Individual Treatment Effects under Multivalued Treatments（2611.32182）｜stat.ME｜Lequn Ge, Gaorong Li, Hui Zhao

**分类**：stat.ME　|　**作者**：Lequn Ge, Gaorong Li, Hui Zhao　|　**链接**：https://arxiv.org/abs/2611.32182

**问题背景**：ITE 的 conformal 推断多限于二元处理；多值处理下，**倾向性得分导出的权重统计不稳定**（方差随处理数爆炸），而连续预测区间又常常横跨潜在结果分布各模态之间的**低密度区域**，导致预测集低效。

**方法**：结合 **KuLSIF 密度比估计**与由条件密度估计导出的 **HPD（最高预测密度）conformal score**，构造多值处理下反事实结果的自适应预测集；两个估计量共享 RKHS 最小二乘形式，因而理论推导统一。对异方差与多峰结果分布稳健，并**主动剔除模态之间的低密度区**。在无混淆（unconfoundedness）与常规条件下证明：协变量偏移下收敛到最优 HPD 集，且具有**渐近条件有效性与统计有效性**。

**主要结果**：模拟研究与 ACIC 基准上，**经验覆盖率贴近名义水平**，且在多峰结果数据上**平均区间长度短于**传统分位数型 conformal 方法。

**与 Reliable Agent·统计推断的关系**：这一篇把三件事串起来：**权重不稳（方差）→ 区间过宽（效率损失）→ 分布形状被忽略（Goodhart 式"钻空子"）**。这正是 agent 做统计推断时最常见的三种病：代理模型不稳导致推断不稳、区间过宽导致"什么都敢说"、以及在低密度区域给出看似合理实则不可实现的建议。最后一条与 2611.31319（conformalized OOD gating 审计反事实建议）互相呼应——都在处理"优化器钻空子"。

## Towards Realistic Evaluation of Uncertainty Quantification for LLM-Based Recommender Systems（2611.33036）｜cs.IR cs.CL cs.LG stat.ML｜Hao Wu, Sipeng Chen, Weikai Li, Tianyi Chen, Qiancheng Yang, Hang Zhou, Yizhou Sun, Wei Wang, Xiao Luo

**分类**：cs.IR cs.CL cs.LG stat.ML　|　**作者**：Hao Wu 等 9 人　|　**链接**：https://arxiv.org/abs/2611.33036

**问题背景**：LLM 排序输出需要可靠的实例级不确定性监控，但 LLM ranker 没有标准的 item-classification head，其分数依赖选项标签、提示、生成流程与可见证据；现有 UQ 方法从不同来源取不确定性、用在不同环节（有的评已发出的排序，有的用不确定性改排序），**直接比较本身就不可靠**。

**方法**：构造 **fixed-ranking 基准**，在统一的输出契约下把 **8 种异构 UQ 信号**当作 record-level 监控器来评测；在 **4 个推荐数据集 × 2 个 LLM backbone** 上以共享的 fixed-ranking 协议运行。

**主要结果**：① **UQ 方法的优劣排序会随 backbone 改变**，即使在同一批参考实例上——说明校准结论不可跨模型迁移；② 与排序对齐的 **Top10Mass** 在若干评测条件下对 Error@10 的标量检出最强（体现 cutoff 对齐的监控优势），但在长尾目标上优势收窄；③ 标量 UQ 信号**难以判断哪个对照组的 clipped NDCG@10 差异更大**，而**来源特定信号**（Perturbation Rank Instability、简单的 listwise 距离）在成对对照一致性上更强。作者据此主张：应当把"排序失败检出"、"跨条件稳健性"、"对受控证据变化的响应"当作**三种彼此独立的性质**分别评测。

**与 Reliable Agent·统计推断的关系**：这是"评测装置自身可信度"线索今天最硬的一块证据——**同一套 UQ 方法换个模型就换了名次**，等于说"报告出来的校准/不确定性结论是模型绑定的，不能外推"。方法论上第三点尤其对用户有用：把"检出失败"、"稳健性"、"对受控证据的响应"拆成三个独立指标，其中"成对对照 + 受控证据扰动"的思路正是 e-value / 序贯推断中**受控比较**的标准做法（可与 2611.31539 的 e-value 序列对接）。

## Agentic Systems Need Multi-Run Evaluation: A Study of Retrieval and Response Variability in a Deployed Enterprise RAG System（2611.31266）｜cs.CL｜Karan Gupta, Sumit Bhatia, Yunyao Li

**分类**：cs.CL　|　**作者**：Karan Gupta, Sumit Bhatia, Yunyao Li　|　**链接**：https://arxiv.org/abs/2611.31266

**问题背景**：RAG 系统历来在单次运行下评测；agentic RAG 引入了一个新来源——**同一问题重复运行会给出不同结果**，因为检索阶段是非确定性的（例如 agent 每次发起不同数量的并行搜索 → 检索到的文档不同 → 最终答案不同）。单次运行评测因而可能把系统性问题藏起来。

**方法**：在一个**已部署的**企业级 agentic RAG 系统（产品文档问答）上，把 **739 个问题各跑 10 次**，逐一比对执行轨迹，定位不同运行**第一次分歧**发生在哪一步。

**主要结果**：检索命中率在"**任一次运行**找到正确页面"时为 **69.4%**，而在"**全部 10 次**都必须找到"时只有 **50.9%**——差近 19 个百分点；回答**语义相近但措辞不同**（平均 BERTScore 0.90、BLEU 0.49）。轨迹级分析显示**检索是分歧的最大来源（43.9%）**，仅"第一次检索步骤发起的并行搜索数量"一项就占了分歧对（divergent pairs）的 **20.1%**。结论：单次运行评测会掩盖 agentic RAG 的可靠性与一致性问题，**必须多运行评测才能暴露**。

**与 Reliable Agent·统计推断的关系**：这是最朴素、也最常被忽略的一类偏差——**单次运行 = 单点估计**，报告时却不附方差，任何单次评测结论都可被"选到最好那次"污染。69.4% vs 50.9% 这组数字说明"至少成功一次"和"每次都成功"之间差出一个量级风险，而这正是 agent 上线时真正要关心的量。方法上（同一问题重复运行 + 找首次分歧点）就是最朴素的方差分解 / 稳定性分析，可与任何 agent 基准叠加使用，几乎零成本。

## Spec-Test Coverage Gap: Detecting Overspecified Tests in SWE-Bench-Style Benchmarks（2611.31839）｜cs.SE cs.AI cs.LG｜Avi Aggarwal, Yiran Hu

**分类**：cs.SE cs.AI cs.LG　|　**作者**：Avi Aggarwal, Yiran Hu　|　**链接**：https://arxiv.org/abs/2611.31839

**问题背景**：SWE-bench 类基准用"当初修复该 issue 的那次改动所带的测试"来判定 agent 是否解决正确。但这些测试**可能强制了任务描述里从未提出的细节**，导致同样正确的替代修复被判失败。此前这类"过规范测试（overspecified tests）"主要靠**昂贵的专家评审**才能发现。

**方法**：定义 **Spec-Test Coverage Gap（STCG，1–4 级）** 度量过规范程度，由两个 LLM 裁判（Claude Opus 5.5、GPT-6.1 Sol）在给定规格说明与测试补丁后打分，**两个裁判都 ≥3 分**才标记为过规范。研究分三部分：① 在 206 个人工审计已标注为"过规范 / 正常"的任务上**验证裁判**；② 对全部 500 个 Verified 与 731 个公开 Pro 任务打标，与 Verified 前 30 名提交的结果对比；③ 让 Claude Opus 5.5 **放松**被标记任务的过规范要求，重新判分这 30 个提交里 **2186 个失败补丁**。

**主要结果**：① **裁判可用**：在验证集上正确标出 **89%** 人工认定的过规范任务，误标率仅 **4%**（把已知正常的任务错标为过规范）；② **过规范很普遍**：全基准上标出 **23% 的 Verified** 与 **35% 的 Pro** 任务；③ **被标记的任务对 agent 极难**：Verified 前 30 名平均只解决 **31%** 的被标记任务，而其他任务是 **88%**；④ **榜单会被改写**：放松测试后，2186 个失败补丁中 **61%** 变为通过，等于给每个前 30 名提交**加 33–60 个任务**，resolve rate 最多提升 **12 个百分点**。

**与 Reliable Agent·统计推断的关系**：这是"**评分装置的缺陷被算成了 agent 的能力缺陷**"的教科书案例，也是今天最刺眼的一篇：一半以上的"失败"其实是测试写错了。可迁移的框架非常清晰——**先审计测量装置（用双裁判 + 人工验证集建立 89%/4% 的混淆矩阵），再谈模型排名**。这套"双裁判 + ≥3 分 + 在人工标注集上先验证"的协议，几乎可以原样搬到"给 agent 做评分的 LLM 裁判"上，做法与 2611.33012、2611.33065 互补：这一篇负责"发现并量化测量偏差的规模"，另两篇负责"裁判能识别什么、漏掉什么"。

### Can LLM Judges Catch Unsafe Clinical Actions? A Fault-Injection Study（2611.33012）｜cs.AI cs.CL｜Neda Ghafouri

**链接**：https://arxiv.org/abs/2611.33012

向 MedAgentBench 的**已验证**轨迹注入受控临床错误，得到 416 条故障轨迹、8 类错误、6 个开源 LLM 裁判。只给最终答案时，裁判**无法分辨"错误但答案未变"的轨迹，反而把 56% 的正确轨迹误标为不安全**；给出完整轨迹后区分度达 0.75；再加入真实 EHR 响应，区分度再提升 0.39。反直觉的是，**加入 agent 的推理过程反而让性能变差**，对"上报了错误临床数值"这类最难错误的检出反而下降 0.18；MedGemma 弱于通用模型，且是唯一漏掉潜在危险用药过量的裁判。原基准的评分器**全部放行**了 38 条故意跳过化验检查的轨迹，而 LLM 裁判 + 基于规则的检查器组合可检出 **97%** 的注入故障。**要点**：裁判的可靠度必须用"故障注入 + 误报率"单独测量；给裁判更多信息未必更好（reasoning 会引入干扰）。

### Calibrated Reading of Latent Reasoning and Communication（2611.32143）｜cs.LG cs.AI cs.CL｜Zixi Wang, Gaohao Zhou, Yubo Huang, Xin Lai, Yushe Cao, Jingzehua Xu, Shuai Zhang

**链接**：https://arxiv.org/abs/2611.32143

提出 **CLR（Calibrated Latent Reader）**：一个紧凑 transformer，通过"状态 × 候选答案"的任务条件交互来预测推理结果与通信内容；源适配器支持跨模型迁移，**conformal 校准在可交换性假设下提供覆盖率与误报保证**。结果：在两个 CODI 模型上，最终答案预测与参考值归属相对 MLP / 注意力探针提升 **4–18 个百分点**；在 CODI-GPT-2 上以 **437–648 倍更少**的推理 FLOPs 达到与 1.7B LatentQA verbalizer 相当的准确率；在合成 Qwen3-4B 通信任务上，把解码事实与"公开承诺"对比，可在名义 **5% 误报率**下检出 **93.1%** 的消息替换。**要点**：这是"给模型内部读数配保证"的范式——可解释性探针从"看起来相关"升级为"有覆盖率与误报承诺"，正是把 agent 自述变成可核验证据的一步。

### Pragmatic Deeply Debiased ML（2611.33069）｜econ.EM stat.ME｜Victor Chernozhukov, Chengchun Shi

**链接**：https://arxiv.org/abs/2611.33069

DML（双稳健机器学习）用"拟合结果回归 + 加权残差"消掉**一阶**正则化偏差，但当**回归误差与加权误差同向**时仍残留**二阶偏差**。本文针对二阶项：训练一个强学习器从大量协变量预测第一阶段残差，得到一维（或低维）working model，其偏差贡献在**独立样本**上估计；同时分析一般的核方法修正（协变量分块、平滑器）。理论结果：**深度去偏 ML 在代数上等价于"普通 DML + 一个事后回归更新"**。经验上，强初始 DML 学习器常常使二阶修正相对于抽样不确定性**很小**，此时该修正的价值是作为**诊断检查**，并与"剩余错设偏差"的敏感性界并用。**要点**："去偏之后还剩多少偏差"正是用户课题的核心追问——这篇给出的是二阶偏差的可操作估计 + 独立样本 + 诊断式结论（而非新方法），很适合作为 agent 推断偏差分析的统计底座。

### SecondChance: Benchmarking Reliable Error Recovery in AI Agents（2611.31586）｜cs.CL｜Atahan Dokme, Adar Avsian, Larry Heck

**链接**：https://arxiv.org/abs/2611.31586

构造错误检查点数据集与评测框架，考察 agent 出错之后的恢复行为。错误是**天然的**——来自 agent 自己在 τ²-bench、BFCL、AppWorld 中的尝试；随后从同一检查点以四种条件恢复（无提示 / 告知出错 / 告知出错位置 / 给出修复指引），测量纠错率、任务成功率、策略合规、环境状态保持、修复持久性与成本；**12 个模型 × 4 条件 × 5760 次续跑**。结果：**恢复极其罕见**——最好的模型在无协助下也只完成 **16%** 的恢复，有修复指引时 **27%**；**"改对"≠"恢复"**：Llama-3.3-70B 在有指引时纠正了 26% 的 τ² 错误，却一次都没完成恢复；AppWorld 中 40 条"成功"的续跑**把错误留在原地**。**要点**：只看任务成功率的评测会漏掉"错误是否被真正修复"——这正是任务成功率与真实可靠性之间的偏差；两者的差值本身是个值得单独报告的指标。
