## Anytime-valid goodness-of-fit test by $e$-spacings（2611.23775）

`stat.ME`、`math.ST`、`stat.TH`｜Yunda Hao, Kin Wai Chan

**问题背景.** anytime-valid（随时有效）拟合优度检验要求在**任意停止规则**下控制 I 类错误。这是 agent 场景里最刚性的统计保证需求：agent 会反复迭代直到「看起来显著」，若用固定样本 p 值，每次偷看一眼都破坏有效性。

**方法.** 基于顺序统计量的**最大间距**构造 spacing-based $e$-process（作者称之为 $e$-spacing tests），对分布做非参数检验；程序简单、计算高效、功效一致（power-consistent）。该构造对数据生成密度与零假设密度之间的**局部差异**尤其敏感。进一步把「最大间距」推广为「最大的 $m$ 阶间距中的 $1/k$ 比例」所构成的集合，用以刻画密度的下水平集，从而在更**全局**的差异下提升功效。再提出贪心可预测方案（argmax 或 softmax 规则）来组合多个 $e$-spacing 检验策略，并证明该方案最优地调优 $e$-spacing 检验。经坐标逐维 Rosenblatt 变换可推广到多元检验。

**主要结果.**

- 在温和条件下，所构造 $e$-process 的**对数与 oracle 最优 $e$-process 渐近等价**（即只损失常数级信息）。
- 仿真中，所提方法相对所考虑的 anytime-valid 竞争方法、以及各种**多重检验校正的 Kolmogorov–Smirnov 检验**，均表现良好。
- 理论结果同时覆盖「局部差异」与「全局差异」两种偏差形态，对应到不同构造（最大间距 vs. 间距集合）。

**与 Reliable Agent · 统计推断的关系.** **填补了本方向长期为空的缺口。** 之前多日日报都记录「e-value / always-valid 真实命中 0 篇」，今天终于有了方法论层面的正样本，而且它恰好落在旅行者最需要的场景上：agent 自主决定何时停下来做检验。可迁移点有三：其一，$e$-process 只需**有效分数**，因此可以直接把 agent 的中间产出（如每次迭代的统计量）转成 $e$-value，无需重跑整条流水线；其二，其「局部差异敏感」的性质适合诊断「agent 在哪个子群体/哪个子任务上系统性偏离」；其三，贪心可预测组合多个 $e$-process 的做法，天然对应 agent 在多条策略间自适应选择时的多重检验问题。

**链接.** https://arxiv.org/abs/2611.23775

## A Local False Discovery Rate Framework for Compound p-values（2611.24555）

`stat.ME`｜Jierui Zhu, Rina Foygel Barber, Nikolaos Ignatiadis

**问题背景.** 复合 p 值（compound p-values）把「单个 p 值有效」放宽为「跨零假设的**平均**条件」。但这种灵活性**未必保护个别拒绝**，尤其当与 FDR 这类同样是平均误差准则搭配时。这是一个在 agent 并行跑大量假设时极易踩到的坑。

**方法.** 引入 **density-compound p-values** 这一新概念，把复合 p 值与频率派 **local FDR** 范式连接起来。在独立性假设下，为 **support-line (SL) 程序**建立**边界 FDR（bFDR）**保证，并对加权 p 值与 compound-e-weighted p 值给出名义水平控制。对一般的 density-compound p 值，界依赖一个**可处理的零分布参数**；理论还可延伸到由**置换检验池化**构造的离散复合 p 值。

**主要结果.**

- 核心负面结果：**若无对该零分布参数的进一步限制，bFDR 可显著超过其名义水平**（即程序本身给出的是名义控制，实际失控）。
- 正向结果：独立性下 SL 程序具有 bFDR 保证，且对加权 / compound-e-weighted 变体成立。
- 应用：在**低分辨率检验问题**中给出方法示例——此时单独有效的置换 p 值过于粗糙，做完多重校正后无法产生任何发现。

**与 Reliable Agent · 统计推断的关系.** 与旅行者的 bias 课题高度互补。「平均条件下的有效性不保护个别拒绝」几乎是为 agent 场景写的：agent 一次生成几十个假设、每个假设各自给一个 p 值，整体看「平均 FDR 还行」，但**真正被拒的那几个到底假不假毫无保证**。可迁移的结论是：报告 agent 发现的统计量时，除了整体 FDR，必须额外给出**局部/边界**错误率证据；在低分辨率（样本量小、指标离散）时，复合 p 值 + 置换池化是可行路径，但需要显式检查文中那个「零分布参数」是否满足额外限制，否则 bFDR 名不副实。

**链接.** https://arxiv.org/abs/2611.24555

## MANGO Arena: Same Seeds, Different Chains — Evaluating LLM Agents in a Disrupted Supply Chain（2611.23613）

`cs.MA`、`cs.AI`｜Sara Amar

**问题背景.** 评估 LLM agent 在串行供应链中经营一家公司时，需要同时度量三件事：经济结果（**牛鞭效应**）、压力下的规则遵从、以及串谋提议。难点在于：这些 agent 系统的输出本身带**随机性**，而评测结论很容易被这种随机性而非模型差异所决定。

**方法.** 开源测试台 **MANGO Arena**，改编自课堂工厂管理游戏 MANGO：四个 LLM agent 各运行一家公司，处于串行供应链中。环境强制硬规则（卡车运力上限、禁止赊账的现金约束、生产能力上限），**记录每一次为破坏规则而被阻断的尝试**，并提供公开留言板（禁止明面上的资金侧交易）。试点规模：三个小推理模型 + 两个脚本参考策略 × 两个条件（有/无供应商火灾）× 三个需求种子。

**主要结果.**

- 经济结果：所有 LLM agent 都把需求波动**向上游放大**——零售端 **7–25 倍**、供应商端 **13–179 倍**，常超过教科书的 order-up-to 策略；主因是**批量下单**（最高 60% 的决策为「零下单」）。
- 行为结果：真实规则违规很少（每模型 288 次决策中**最多 7 次**），且无人提出金钱侧交易。
- **评测方法层面的关键发现（本文主贡献）**：（一）**API 失败（限流、失控的隐藏推理）静默进入指标**，被当作「不下单」决策；（二）用**相同种子**重跑且无失败调用时，上游牛鞭效应在两次运行之间**最多变化 17 倍**；（三）只用三个种子时，「某种干扰如何影响某模型」的结论**在重跑后不成立**。
- 作者完整公开了这些失败，并据此提出该类多 agent 评测的报告规范。

**与 Reliable Agent · 统计推断的关系.** 本期最刺眼的一篇：**同样的随机种子都不足以让 agent 评测复现**。对旅行者课题有三重含义：其一，「API 失败被静默编码成一种行为」是典型的 **measurement error**——把系统故障记作 agent 的保守决策，会系统性压低某些指标（如牛鞭效应），这类偏差在任何 agent 统计流水线里都极易被忽略；其二，三个种子的结论不可复现，直接说明**报告 agent 结论必须报告重复次数与方差**，单点对比没有意义；其三，规则遵从率这类「看起来很干净」的指标也可能只是 API 稳定性的影子。建议把「同种子多次重跑 + 显式记录失败调用」写成 agent 评测的强制协议。

**链接.** https://arxiv.org/abs/2611.23613

## A Capability Framework for Evaluating Agentic AI Platforms in Regulated Enterprises（2611.24039）

`cs.AI`、`cs.MA`、`stat.ML`｜Abbas Raza Ali, Muhammad Ajmal Siddiqui, Moona Zahid

**问题背景.** 企业采购 agentic AI 平台的速度已经超过测量能力：公开 agent benchmark 只在固定 harness 里给**模型**打分，而企业买的是**整合平台**——编排、记忆、治理、工具层才决定结果，而且大多凭厂商演示采购。

**方法.** 某全球银行创新实验室的工业评测项目（「bakeoff」）：**10 个平台**（开源框架 / 专有产品 / 云厂商生态），由跨职能评审组在 **9 个能力维度 × 3 个金融工作负载**（交易对手信用风险、RAG、流程自动化）上评估；再做一次二次分析检验评分的维度结构；最后据经验教训提出协议。

**主要结果.**

- 评分把平台稳定地分为**三档**，且在替代权重下稳定；同时暴露出被总分掩盖的**负载特定**强弱。
- **二次分析发现严重的光环效应**：名义上不同的 9 个维度之间 **Cronbach's alpha = 0.98**，其中 8 个维度与总分的**秩相关 ≥ 0.93**——即这种打分**测的是演示呈现度而非能力**。
- 提出「**先门槛后打分**」的四层协议：能力层、执行可靠性层、治理门槛层、业务价值层；其中执行可靠性层要求**在重复运行上估计的 trace 级可靠性指标**，另配**自主性就绪度刻度**与**可复现性协议**。
- 作者明确划界：陈述当前证据支持什么、以及需要受控 harness 补什么，才能把企业平台评测从「结构化判断」变成「测量」。

**与 Reliable Agent · 统计推断的关系.** 给出了一套可以直接抄的 agent 可靠性测量骨架，其中三点对旅行者课题尤其关键：其一，**「trace 级可靠性 × 重复运行」**正是评估 agent 统计输出所需的方差控制协议——与 MANGO Arena 的复现失败互为印证；其二，**Cronbach α = 0.98 + 秩相关 ≥ 0.93** 是「评测量表测的是单一潜在构念」的量化负证据，提示 agent 能力多维度的公开榜单极可能只是演示度的重命名；其三，「先门槛后打分」把**可靠性与能力分离**（能力 = 会做；可靠性 = 稳定做对），与今日 2611.24932 的「价值由校准决定」在结论上呼应。

**链接.** https://arxiv.org/abs/2611.24039

## On Evaluating User Simulators for Interactive Agents（2611.24892）

`cs.LG`｜Hengguang Zhou, I-Hung Hsu, Li Chen, Priyanshi Shrivastava, Anastasios Angelopoulos, Wei-Lin Chiang, Ion Stoica, Cho-Jui Hsieh

**问题背景.** user simulator 是规模化评测交互 agent 的标准手段，但**它本身的质量如何评估**一直欠研究。结果是：一个高 benchmark 分数到底说明了什么，并不清楚。

**方法.** 做**（元）评估**：先故意扰动模拟回放以人为诱发失败（改变目标、遗漏约束、过早停止、接受残次工作，共 10 种扰动），再看既有评估指标是否会惩罚这些失败；据此提出新的评估套件，包含「模拟器对评测 agent 的效用」+ 两种保真度度量：**population-level fidelity**（群体交互模式）与 **trace-level fidelity**（单个用户的目标/约束/角色是否被保留）。

**主要结果.**

- 三个先前研究提出的评估方法**只检测出 10 种扰动中的 5–6 种**；更糟的是，它们的**合成分数甚至偏好**「被指示接受坏工作」的群体，而不是未修改的对照。
- 新提出的套件在**相同检测标准**下能检测**全部 10 种**扰动。
- 在 **351 轮真实多轮会话**（**348 名用户、23 种语言**，协作产出全栈 web 应用、游戏、设计资产、自动化工作流）上评测 6 个模拟器：**population-level 度量会漏掉**模拟用户走错目标、忽略约束、脱离人设的情形，凸显出需要在更细粒度上评估保真度。

**与 Reliable Agent · 统计推断的关系.** 「**评测指标的效度**」问题，与 2611.24039 的光环效应互补：如果用来评价 agent 的指标本身只查得出 5–6 成失败，那么基于该指标的 agent 统计结论就系统性地继承了测量偏差——而且这种偏差方向未知、难以事后校正。对旅行者课题的直接含义是：**任何以模拟环境/模拟用户替代真实分布的 agent 推断，其可信度上限由模拟器的保真度决定**，因此在 agent 统计流水线里，模拟器评测应当是**受评对象的一部分**而不是脚手架。

**链接.** https://arxiv.org/abs/2611.24892

## Knowing What You Know: A Trait Theory of Reviewer Value in Human-AI Cognitive Systems（2611.24932）

`cs.AI`、`cs.CE`、`cs.HC`、`cs.LG`｜Priyanka Sinha, Sugam Pandey

**问题背景.** 当一个强模型与人类评审者共同做同一个决策时，**谁还带来增量价值**？作者的回答是：这取决于一个单一认知特质——**元认知校准**（行为置信度与判断实际正确性之间的对齐）。

**方法.** 提出「评审者价值特质理论」，包含五条主张：价值由**校准**而非活跃度、速度、共识或资历决定；校准会在行为遥测中留下可观测痕迹；这些痕迹**单独看不可诊断**（一个校准良好的专家的「快、少改」特征与一个自信的新手无法区分，除非用结果去 gate）；人类校准与模型的自知是**同一构念**，因此联合系统应逐题交给校准更好的那一方；个体校准的**因果可识别性只在单次判断之上**才存在。实证基于某 AI 辅助会计系统**六个月的生产窗口**。

**主要结果.**

- 数据规模：**541,621 次评审事件、483 名评审者**。
- **纯行为专家画像会颠倒真相**：过度自信群体的「纠错存活率」仅 **5.2%**，却被评为高于真正的专家（**99.2%**）。
- 评审者质量在**任职年限上是持平**的 → 校准这一特质**不是在职学到的**。
- 把区分好/坏评审者的同一套校准逻辑用在**模型**上，可把 **92.5% 的人类精力**集中到真实错误上。
- **理论边界（对旅行者课题最关键）**：在**多数投票聚合**下，单个个体的**因果价值不可识别**。

**与 Reliable Agent · 统计推断的关系.** 两条结论对「Agent 做统计推断时的 bias」是直接的。第一，**可靠性指标应当选校准而非能力**——一个自信而错的 agent 比一个能力弱但知道自己不对的 agent 更危险；这为「什么时候应该相信 agent 的输出」提供了比准确率更合适的判据。第二，作者给出的边界条件非常关键：**在多数投票聚合下，单个 agent 的因果价值不可识别**。这意味着「用 N 个 agent 投票做统计推断」时，不能把最终结论的准确性归因到某个特定 agent 的贡献，也意味着投票聚合本身会**抹掉**个体层面的校准信息——是聚合设计层面的一处信息损失，与 bias 机制直接相关。

## A level is not a rank: an empirical audit of quantile-to-index conversion in 10 released conformal-prediction libraries（2611.23329）

`cs.SE`｜Shivam Lalakiya

**问题背景.** 一个 0.90 的 conformal 区间只在**正确的 rank** 上保持保证：新分数落在 n 个分数中第 r 小或以下的概率为 $r/(n+1)$。但被审计的库把 **level 传给分位数函数**，得到的位置可能落到别处——于是「90% 覆盖」的声明名不副实。

**方法.** 审计 10 个**固定版本**包中 **39 处**「level 变成 index」的调用点（具名集合，非系统检索）；其中 12 处通过实际运行分类、11 处通过它们共享的 numpy 方法判定、其余读源码；再把**覆盖率与所需 rank 在同一组分数上配对**比较。

**主要结果.**

- **7 个表格实现全部到达所需 rank**（这一面是好的）。
- **darts** 中一条代码路径上：rank 一致处覆盖率变化 **0.0000**，rank 不一致处覆盖率**低 0.0280–0.0560**（即低 2.8–5.6 个百分点）；另一归档重复了这种分裂但区间范围不同。
- **低于可行性下界** $n < 1/\alpha - 1$ 时，**14 条公开调用路径中有 5 条静默返回有限数值**，其余抛错或告警；**statsforecast 的默认校准低于其下界**。
- 产出：分位数接口只接受 level 这一事实被写成文档；**6/19 个上游 issue 已合并**，其中一个修复了覆盖率不足；另给出按「到达的 rank」分类的 **conformance suite** 与审查清单。

**与 Reliable Agent · 统计推断的关系.** 这是本期最刺眼的一类**实现层偏差**：声称 90% 覆盖的区间，实际覆盖率可能低 **2.8–5.6 个百分点**，而且**静默发生**（无异常、无告警）。在 agent 场景里，这类缺陷会直接进入 agent 生成的置信声明，而 agent 又会把它当作事实转述——链条上没有任何一环会察觉。两条可直接落地的结论：（一）在 agent 统计流水线中，对 conformal/risk-control 实现跑一遍 **conformance suite**（按到达 rank 分类，而非按接口名字分类）；（二）任何 conformal 区间都要在**报告里同时写明 $n$、level 与可行性下界 $n \ge 1/\alpha - 1$**，否则覆盖率声明无意义。

**链接.** https://arxiv.org/abs/2611.23329

## Distribution-Free Uncertainty Quantification for Weather Forecasting: Conformal Prediction Under Spatiotemporal Dependence（2611.24329）

`cs.LG`｜Mariya

**问题背景.** conformal prediction 给出有限样本、分布无关的**边际覆盖**，并已开始用于格点天气预报。但边际覆盖只关心「某点上被覆盖点的长期比例」，**不关心在给定某一天上，覆盖在空间与时间上如何联合表现**。

**方法.** 基准 **8 种区间构造过程**（Gaussian、pooled 与 per-cell split conformal、per-season、adaptive conformal inference (ACI)、rolling windows），用于格点 2m 气温预报、**8 个 lead time**（6 小时到 10 天），数据为 ERA5（5.625° 分辨率）、一个刻意朴素的卷积 forecaster 与 ECMWF 业务系统 **HRES**；2017–2018 校准、2019–2021 测试。除覆盖、宽度、interval score 外，还报告**依赖诊断**：空间过度离散指数、逐日空间覆盖的分位数、以及 miss 持续性相对「打乱日期」零假设。

**主要结果.**

- per-cell 方法达到**接近名义的边际覆盖**，但「一天中被覆盖格子比例」的**日间方差约为独立情形的 3–10 倍**，且 **miss 在时间上聚集**；两者随 lead time 增长（CNN），HRES 亦然，且**所有方法共有**。
- 一个 oracle（把每天的归一化误差除以当天均值）能消除 **81–92%（CNN）/ 93–98%（HRES）** 的超额离散 → 说明大部分超额来自跨格点的「大误差日」。
- 用季节项与已验证误差预测出的 **day-scale** 可降低过度离散指数且**不需加宽区间**，但 interval score 改善**最多 0.6%**；HRES 上 12 小时–3 天区间 day-scale 有最低过度离散指数，而 ACI 或季节条件校准有最佳 interval score → **没有方法两头都最好**。
- 局限自陈：单一变量、单一粗网格、再分析目标、两个 forecaster。

**与 Reliable Agent · 统计推断的关系.** 「**边际覆盖 ≠ 联合覆盖**」是 agent 给出逐点置信声明时最经典的陷阱，本文把它量化成了「日间方差 3–10 倍、miss 时间聚集」。这对 agent 场景尤其现实：agent 逐题/逐任务给出置信度，如果这些置信度在时间或任务维度上高度相关，那么「整体看起来有 90% 覆盖」并不意味着任何单次决策有 90% 的正确概率。第二条结论同样可迁移：**不同的不确定性量化目标（离散度 vs. 区间分数）对应不同的最优校准方法**，不存在「一个 conformal 配置通吃」，agent 论文里常见的「用 conformal 包一下」需要先说清目标函数。

**链接.** https://arxiv.org/abs/2611.24329

## Risk-Controlled Correction for Frozen Multimodal Models under Missing Modalities（2611.23886）

`cs.AI`、`stat.ML`｜Hoang Pham Cong, Long D. Nguyen, Ho Viet Duc Luong, Nguyen Tran Minh Nhat, Binh P. Nguyen, Huynh Thi Thanh Binh

**问题背景.** 已部署的多模态预测器可能在其权重无法再改的情况下遭遇**模态缺失**。训练期的修复回答不了「残余误差里还有多少是**仍可纠正**的」。

**方法.** 证明这部分误差由 **Bayes gap** 刻画（模型预测与「在已观测模态下的 Bayes 预测」之差）：对交叉熵与平方损失，超额风险以损失几何度量该 gap，而**已观测模态本身的模糊性不可消除**——因此**严重退化的预测未必是可纠正的预测**。估计 Bayes 预测通常需要标签，但若「观测更多模态的模型是条件正确的」，则把它的输出在剩余模态上做条件平均即可在**无检索标签**下恢复该目标，且与平均硬标签相比在期望交叉熵或 Brier 风险上不劣——但这类假设**不可避免**，否则目标在无标签数据上不可识别。提出 **GUARD**（Gated Utility-Aware Recalibration for Deployment）：**不改动已部署的预测器**，用检索估计候选修正、从部署匹配的有标签数据学习修正是否有帮助、并在留出集上用 **conformal risk control** 校准阈值。

**主要结果.**

- **可交换性**下，GUARD 施加「修正导致的损失增加超过给定容差」的**边际概率被限制在预设水平**，且该界**与学到的分数无关**。
- 受控实验显示：修正收益取决于 **headroom**（还有多少可纠正空间），而**不是原始误差大小**。
- 在跨 **6 个领域、9 个冻结模型-数据集对**上，GUARD 在伤害预算内保留了 blanket correction 的**大部分收益**，而 blanket correction 常常超出该预算。

**与 Reliable Agent · 统计推断的关系.** 两个可直接搬进 agent 流水线的东西。其一，**「Bayes gap = 可纠正误差」是一个干净的 bias 分解**：把「模型错了」拆成「错了但无法纠正（信息不足）」与「错了且可纠正（能力/表示不足）」，前者需要收集更多信息，后者才值得触发自我修正——这正是 agent「要不要再试一次」决策所需要的判据。其二，**conformal risk control 控制的是「修正动作的风险」而不是「预测的覆盖」**，这是一种与覆盖保证不同形态的保证，正适合「agent 决定是否自我修正」这种动作型决策。

**链接.** https://arxiv.org/abs/2611.23886

## Can LLMs Understand What They Predict? Evaluating Latent Causal Structure Inference in Financial Markets（2611.23533）

`cs.CL`、`cs.LG`｜Yixiang Zheng, Yuechen Jiang, Zhiwei Liu, Jimin Huang, Yuyan Wang, Sophia Ananiadou

**问题背景.** LLM 越来越多地通过「能否预测未来结果」被评价，这**隐含假设**预测成功反映了对其背后系统的理解。但**准确预测常可在根本没有恢复潜在机制的情况下达成**。

**方法.** 提出 **LUCID** 基准：模型从事件描述与历史金融观测出发，生成**事件诱发的因果图**表征其推断出的市场结构，再用**重建式（reconstruction-based）框架**评价该结构的质量。

**主要结果.**

- 对 **6 个开源与专有 LLM** 的评测：**加入它们生成的因果图通常降低重建质量**（相对于只用历史观测），尽管少数指标有所改善。
- 结论：对这些 LLM 而言，**从可观测证据推断出有信息量的事件特异市场结构仍然困难**。
- 换言之：LLM 生成的因果图在这里不是「额外的结构信息」，而是一个**主动的噪声源**。

**与 Reliable Agent · 统计推断的关系.** 本期与旅行者课题最直接同构的一篇。常见做法是「让 agent 输出因果图/结构假设，再据此做推断」——本文给出反面证据：**LLM 生成的因果结构不但没有帮助，反而把重建质量拉低**。也就是说，这条路线引入的不是无害的噪声，而是**系统性的负向偏差**。可迁移结论：不要把 agent 产出的结构当作可用的先验；若要用，必须先用重建式/反事实式的外部判据**验证该结构确实带来增益**（LUCID 的重建框架本身就是现成的验证器），否则应退回只用原始观测的基线。

**链接.** https://arxiv.org/abs/2611.23533

## When Do LLMs Model the Right Target? Problem Formulation in High-Stakes Risk Prediction（2611.23638）

`cs.CY`、`cs.LG`、`stat.ME`｜Jennifer Zhang, Amanda Coston

**问题背景.** 生成式 AI 正越来越多用于辅助数据科学任务，但它能否**正确表述（formulate）**分析问题仍是根本性疑问。本文聚焦效度（validity）挑战之一：**decision dependency**——历史决策会影响观测结果，导致「用历史数据训练出的预测模型被用于决策时，效度被破坏」。

**方法.** 在**儿童福利、医疗、就业**三种设定下，评估 LLM 生成的**代码与解释**对 decision dependency 的处理：使用 **11 个 OpenAI / Anthropic 模型 × 7 种 prompt 条件**；分别判断（i）LLM 生成的代码是否实现了在研究假设下估计目标量的适当程序，（ii）解释中是否承认了 decision dependency。

**主要结果.**

- **没有 prompt 引导时，LLM 不可靠地处理 decision dependency**。
- 当 prompt 明确规定「目标 + 估计它所需的假设 + 估计程序」三件事时，**target-aligned 实现率达到 99–100%**。
- 在前沿模型中，一句简单的「决策如何影响结果」的 prompt 描述就足以诱发 target-aligned 实现。
- 部分回答**在解释里承认了 decision dependency，却没在代码里处理它**（说对了但做错了）。
- 作者结论：分析者**不应依赖 LLM 正确表述预测问题**，除非给出明确的方法学引导并仔细复核；并提出面向效度的准则，覆盖 prompt 构造、目标与估计程序验证、关键假设识别。

**与 Reliable Agent · 统计推断的关系.** **最贴题的一篇**：直接讲「Agent 做统计推断时的 bias」，而且指出最根本的偏差来源不是估计器，而是**目标（estimand）设定错误**。更关键的是它给出了**成本极低、效果确定**的干预：只要在 prompt 里写清「目标 + 假设 + 估计程序」，实现率就从不可靠跳到 **99–100%**。这意味着 agent 统计流水线的第一道关卡应该是**目标与假设的显式声明与复核**，而不是先去调估计器。此外，「解释里承认了但代码里没处理」这一发现提示：评估 agent 统计能力时**不能只读它的解释，必须执行它的代码**。

**链接.** https://arxiv.org/abs/2611.23638

## Confounding Heterogeneity in Multivariate Sensitivity Analysis for Observational Studies（2611.23568）

`stat.ME`｜Anthony Frazier, Siyu Heng, Wen Zhou

**问题背景.** 观察性研究中，即便匹配了**已测**混杂，**未测混杂**仍可能使因果结论有偏，因此通常需要敏感性分析。多变量情形（单一处理 → 多个结果）此前研究不足。

**方法.** 识别出多变量敏感性分析的一个固有特征——**confounding heterogeneity**：不同结果可能受**不同**的未测混杂影响，且同一未测混杂对不同结果的影响程度也不同。在匹配观察研究的基础上，构造出**容纳该异质性**的敏感性分析框架；用 **design sensitivity** 与 **Bahadur–Rosenbaum 效率**研究渐近功效，用数值研究考察有限样本功效。

**主要结果.**

- **关键负面结果**：许多已有敏感性分析方法的一类错误（Type I error）控制，**只在其敏感性分析模型与推断方式根本上不同于经典框架时才成立**——在经典框架下并没有保证。
- 实证结论：**广泛使用的单参数框架在考虑 confounding heterogeneity 时，可能错误刻画**因果结论对未测混杂的敏感性。
- 模拟与一个数据应用说明该现象的实际重要性。
- 注意：这是「**误判**」而非「**保守**」——单参数敏感性分析给出的不是安全余量，而是可能失效的保证。

**与 Reliable Agent · 统计推断的关系.** 对 bias 课题极重要的一篇。当 agent 自动跑敏感性分析并**只报一个 Γ（Rosenbaum bound）**时，它给出的不是「至少有多安全」，而是「在**被误设的**单参数模型下有多安全」——而本文证明这个模型在多结果场景下可能根本不适用。可操作的结论：（一）agent 报告敏感性分析时，必须同时报告所依赖的**未测混杂结构假设**，不能只给一个标量；（二）若结论涉及多个结果或多个处理，需要切换到**容纳异质性的多变量框架**；（三）从 agent 流水线角度看，这是一个「模型选择错误」伪装成「稳健性证据」的典型例子，正是旅行者所说的 bias 的一种来源。

**链接.** https://arxiv.org/abs/2611.23568
