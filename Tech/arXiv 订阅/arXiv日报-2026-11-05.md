### 1. Grounded but Not Immune: Confirmation Bias in Agent-as-a-judge（2611.05662）｜cs.AI cs.CL｜Drake Benjamin Brown, Khushbu Pahwa, Yubin Ge, Salvatore Romeo, Akhil Agnihotri, Yi Zhang, Xiaofei Ma, Daniele Bonadiman

**问题背景**
开放式 agent 任务越来越多交给 *Agent-as-a-Judge*：评估者拿到工具、拿到 agent 的完整轨迹，据此对着环境核验结果。这套做法的前提假设是——「能自己取证 ⇒ 被证据 grounding ⇒ 不会被带偏」。

**方法**
把一个特定线索当作**受控诊断**（明确声明不是对抗攻击）：注入一条虚假的 pre-screening note，署名权威、但对正确判决没有任何证据价值。跨 4 个 judge × 5 个数据集，统计「本来正确的判决被翻转」的比例，并把行为变化归因到三类失效模式。

**主要结果**
- 最多 **40%** 的正确判决被推翻，**即使该 judge 随后确实收集到了决定性证据**。
- 失效模式三分：**over-trust**（先正确核实、再放弃并倒向线索）、**hallucination**（为翻转编造支持性证据）、**under-investigation**（在第一个佐证信号处就停止核查）。
- 两个 Claude judge 的有害翻转中 **over-trust 占 67–75%**；小模型 judge 的三种模式分布较散。
- 轻量缓解手段只能削弱偏差，**无法消除**。

**与 Reliable Agent · 统计推断的关系**
这是今天最直接的「agent 偏差」证据，而且指出了一个容易被忽视的机制：给 judge 加工具、让它自己取证，并**不能**免疫于偏差——偏差源从「看不到证据」转移到了「被权威线索锚定」。做 agent 评测时应把这类 pre-screening cue 当受控变量，并且**报告 over-trust / hallucination / under-investigation 的分解**，而不是只报一个总翻转率：同一个总翻转率可能来自完全不同的机制，纠正手段也不同。

**链接**
https://arxiv.org/abs/2611.05662

### 2. Attributing Agent Failures to Their History Needs an Executed Counterfactual: Toward a Reporting Standard（2611.05650）｜cs.AI｜Egor Pakhomov, Erik Nijkamp

**问题背景**
长程 agent 失败原因的公开解释，通常是在**已完成的轨迹**上贴分类标签：judge 读一遍 transcript，然后给失败命名。作者认为，这类「把 agent 行为归因于其历史」的断言本质上是**推断**，不是干预验证。

**方法**
提出一套报告标准：归因断言必须携带 *intervention-verified* 证据——冻结一个**可执行的中途状态**，只改动 agent 所看到的历史，然后继续执行；并且要在「状态恢复性已被测量」的状态点上进行；同时给出与估计量（estimand）匹配的 *replay certificate*。文中命名了四类操纵（manipulation classes），均已有先例（DoVer、REFLECT、Who&When Pro、Causal Agent Replay 等），但**没有一篇报告 replay certificate**。

**主要结果**
两项警示性测量（作者声明它们本身并不适用该标准）：
1. 某个失败分类体系的「集中度」无法与 benchmark 构造方式分离（调整后优势比 **1.15**，区间跨 1）——也就是说，所谓的「失败集中」可能完全是基准设计造出来的。
2. **hash 完全相同的快照**恢复到同样种子的进程后，24/24 个状态彼此一致，但分别有 **9/24** 和 **20/24** 与实时续跑**不一致**；而把随机流的当前位置一并恢复后，**24/24** 全部与实时运行一致。

**与 Reliable Agent · 统计推断的关系**
这篇几乎是「Agent 做统计推断时的 bias」这一课题的方法论地基：归因结论需要**估计量 + 执行式反事实**，而不是叙述式标签。可直接借用它的 reporting checklist（冻结点选择、可恢复性测量、replay certificate 与估计量匹配）。两项警示测量还给出两条实操纪律：(a) 报告失败分布前必须排除 benchmark 构造带来的伪影；(b) 做反事实复现时必须控制随机流状态，否则「反事实」本身不可复现。

**链接**
https://arxiv.org/abs/2611.05650

### 3. AGORA: Reliability-Aware Aggregation of LLM Judges via Item-Response Theory（2611.05556）｜cs.AI cs.CL｜Junhyung Ahn

**问题背景**
LLM-as-a-judge 是人工评测的常见替代；聚合多个 judge 是矫正单个 judge 偏差的标准做法。但现实是：judge pool 里各 judge 的可靠性差异很大，而用来验证的人工标注集只有**几百条甚至更少**。在这个区间，逐 item 取均值会把弱 judge 和强 judge **等权重**对待；而 Dawid-Skene 这类混淆表模型又必须从**过少的 item** 去估计每个 judge 的误差表，误差自然大。

**方法**
提出 **AGORA**（Aggregation Of Reliability-weighted Assessments），一个 item-response-theory（IRT）聚合器：把所有 item 放到同一条**潜在质量轴**上，每个 judge 用一个 *sensitivity* 参数 + 有序评分阈值刻画。于是 judge 的可靠性是**从全部 item 联合学习**出来的，且**不需要人工标签**。

**主要结果**
- 三个 benchmark 上，AGORA 在大评测集上与 Dawid-Skene **持平或更好**；评测集缩到几百条时**优势扩大**。
- 对越来越不均衡的 judge pool 仍保持准确。
- 一个**无标签的 dispersion 统计量**能**提前**指示信任加权是否有帮助。
- 学到的信任权重与 per-judge 人工效度**同向**。

**与 Reliable Agent · 统计推断的关系**
把「评测者偏差」从一个需要人工标签去估计的问题，变成了**可无标签估计的潜变量模型问题**——这与用户主线（潜变量、效率、统计保证）是同源的思路。对课题的直接价值：当标注预算只有几百条时，Dawid-Skene 的 per-judge 误差表估计不稳，可以考虑 IRT 路线；此外那个**无标签 dispersion 统计量**本身就是一个可以拿来做「这次评测该不该信任加权」预判的诊断量。

**链接**
https://arxiv.org/abs/2611.05556

### 4. When Does Risk-Controlled Throughput Forecasting Actually Control Risk? A Reproduction Study on LEO Satellite Link（2611.06307）｜cs.LG cs.AI cs.NI｜Mayan Sharma, Kriti Saini, Devansh Behl, Suganya R, S. Vijayaragavan

**问题背景**
*Risk-budgeted throughput forecasting* 把 LEO 卫星容量的点预测转成一个保守上界，把「超出上界的比例」压在用户指定的风险预算内，供 admission control 安全使用。作者复现了该方向的 SOTA 方法 **BG-CFQS**。

**方法**
在原作者使用的 3 条 Starlink trace **加上 1 条独立的第四数据集**上复现，并对「保证到底在什么条件下成立」做了切分方式对照（随机切分 vs 连续时间切分）。

**主要结果**（作者强调：新的东西是**经验发现**，不是算法）
1. **风险保证可复现，但依赖校准切分**：随机切分下 3/3 数据集复现出全部已发表量（含 risk-pass）；改成**连续时间切分**——也就是部署中的终端真正面对的情形——只在 **1/3** 上成立。
2. **存在最小可服务预算**：无论怎么切分，方法都无法服务低于 **0.15** 的风险预算（其候选分位数集的低端）。4 个数据集上预算取 0.05 / 0.10 / 0.15 时达到的超出率**完全相同**，最紧处**超出 1.4×–3.7×**。
3. **静态 conformal 校准不能改进排序，只能平移工作点**：在 latency spike detection 上确认——online 校准把 AUPRC 提升最多 **51%**。
4. **group-conditional online recalibration 拆成两个机制**：online 部分复现成功（预算 0.05→0.35 内跟踪误差 < 1%，静态校准偏 16–21%）；**group-conditional 部分不成立**——4 个数据集中有 **3 个**，按任何可用协变量（含实测服务卫星几何）条件化都**劣于不条件化**，且无法预测哪些数据集会受益。

**与 Reliable Agent · 统计推断的关系**
今天最贴题的一篇「反面教材」论文，对「Agent 做统计推断时的 bias」有三条可直接落地的纪律：
- **(i) 切分方式必须报告**：随机切分与时序切分给出的保证可能一个成立一个不成立，差别就出在「校准集与部署分布是否同分布」。
- **(ii) 报保证时必须同时报「最小可服务预算」**：本次复现显示该方法在低预算段**根本没有分辨率**，用户指定的预算被静默地"用坏了"。
- **(iii) 不要默认「加条件化 = 更好」**：在 3/4 数据集上条件化反而更差，且这种优劣**事先不可预测**——这本身就是一种需要建模的「异质性」。

**链接**
https://arxiv.org/abs/2611.06307

### 5. CARM: Conformal Adaptive Risk Masking for Reliable Scientific Super-Resolution（2611.06151）｜cs.AI cs.LG math.PR｜Guangtao Zhang, Haonan Wu, Junxuan Gao, Zhengyang Liu, Zhaoxi Zeng, Zhihao Li, Jianguo Huang, Zhiqiang Liu

**问题背景**
深度学习超分辨率（SR）能重建地球观测的细尺度场，但**重建精度本身不提供「哪些区域可信」的校准规则**。Conformal Mask Calibration（CMC）基于 conformal risk control，把空间不确定性分数转成 trust mask，在可交换性（exchangeability）下控制期望的最坏情况局部失真。但其**固定阈值**在受季节性与偶发事件影响的地球观测流上会失准。

**方法**
提出 **CARM**（Conformal Adaptive Risk Masking），一个在**时序分布漂移**下做自适应空间风险控制的统计框架：维护一组**更新速率不同**的 experts，用**非对称 surrogate loss** 在线聚合它们的阈值提议，在「快速适应分布变化」与「平稳期保持稳定」之间取得平衡。所有更新都是**因果的**，只使用固定延迟之后才可得的成熟反馈，因此可以作用于任何能给出空间不确定性分数的 SR 模型。

**主要结果**
- **理论**：证明时间平均的 mask-conditioned 风险以 **O(1/T)** 速率收敛到至多 **α**，且**不需要分布假设**，对任意 expert 聚合权重都成立。
- **实证**：南海叶绿素-a 日尺度 SR 流上，α=0.10 时经验**违反率 43.49% → 9.38%**，移动平均**超出频率 47.29% → 1.22%**，同时保留非平凡的可信区域。ERA5 风场与 OSTIA 海表温度上跨多个 SR backbone 有一致的相对改进。

**与 Reliable Agent · 统计推断的关系**
「conformal 保证 + 时序漂移 + 在线自适应」三者结合得很干净的一篇，而且给了硬数字（违反率 43.49%→9.38%）。对 agent 场景的可迁移点是：agent 的输出同样有「哪一部分可信」的问题，把不确定度转成 **abstain / mask** 是同一套机制；CARM 的「多速率 expert + 非对称 surrogate loss + 只用成熟反馈」正是应对 agent 输出随环境漂移的可操作方案。需注意其代价与前提：因果性、延迟成熟反馈、依赖一个可用的不确定性分数。

**链接**
https://arxiv.org/abs/2611.06151

### 6. Right, Wrong, or Unfinished: A Competing Risks Framework for Language-Model Reasoning under Token Budgets（2611.05860）｜stat.AP stat.ME｜Boen Jiang, Guanhua Fang, and Wen Yu

**问题背景**
在 token 预算下评估语言模型的表现，需要同时搞清楚两件事：**响应何时结束**、**结束时是否正确**。把两者混在一起当「对/错」二元标签会丢掉预算耗尽这一类信息。

**方法**
提出 **CRATER**（Competing Risks Analysis of Token Expenditure in Reasoning），一个有统计原则的框架：把「正确完成」与「错误完成」当作**不同的竞争事件类型**，把在生成上限处仍未完成的响应视为**行政右删失**（administratively right-censored）。拟合出的分布给出跨 token 预算的**正确完成概率、错误完成概率、剩余未完成概率**，以及期望 token 消耗。

**主要结果**
用 MATH 题目的响应做评估，验证了两个下游应用的价值：
- **生成前路由**：CRATER 引导「模型配置 × token 预算」的联合选择；在假设 token 价格下，相对一个强基线把**平均成本降低 53.39%**，而观测到的正确完成率仍分别为 **96.42%** 与 **97.30%**。
- **重复采样**：把 CRATER 的单次成功概率与已有的 **beta-binomial 校准**方法结合，用来预测 **pass@k**。
- 两个应用都能在生成上限内对**任意指定 token 预算**给出预测，且只需**一个「完成时间 + 正确性」的公共模型**，无需为每个预算单独估计参数。

**与 Reliable Agent · 统计推断的关系**
今天最「统计保证」的一篇，也是对用户课题最直接可用的一篇工具：**预算耗尽不是简单的失败，而是删失（censoring）**。若在评测 agent 时把预算耗尽直接算作答错，会系统性低估 agent 能力并给出有偏结论；CRATER 给出的正是「三种结局 + 三条生存曲线」的正确分解。它同时示范了一条很值得借鉴的工程路线——**用同一个生成模型外推多个预算**，而不是每个预算重新估参数。

**链接**

### 7. Uncertainty-Aware Resource Orchestration for Agentic AI Systems（2611.05392）｜cs.AI cs.DC cs.LG cs.MA cs.NI｜Masoud Shokrnezhad, Tarik Taleb

**问题背景**
LLM 驱动的 agentic 流水线是自主的多步流水线：动态调工具、把观测整合进记忆、迭代直到任务解决或资源预算耗尽。与固定图的工作流不同，它的总算力、带宽、端到端延迟**在派发时是未知的**——它们从运行时的中间观测与随机 token 采样中涌现，表现为**重尾、多模态**的随机变量。这迫使基础设施编排器陷入两难：配置不足会在执行中被限流并违反 deadline，配置过度则浪费稀缺的边缘/云容量。现有调度器要求**已知流水线图**，边缘资源管理方法依赖参数化或平稳的需求模型，两者都不适配 agentic 流水线的非平稳画像。

**方法**
把该设定形式化为「**不确定性感知 agentic 编排问题**」：目标是在派发时预留算力与带宽分配以覆盖实际流水线需求，并以给定概率验证流水线能赶上 deadline。提出 **CRO**（Conformal Reservation for Orchestration）：一个在线算法，把过去执行 trace 的**滑动窗口**转成派发时的资源分配，带有**有限样本、分布无关（distribution-free）的覆盖保证**。

**主要结果**
在多模态、重尾任务组合的异构仿真上，CRO 是**唯一被评测方法中能同时在所有风险水平下满足目标概率覆盖**，同时在「覆盖可行」的方法中**过预留最低**——约为 Chebyshev 界基线的**资源浪费减半**。

**与 Reliable Agent · 统计推断的关系**
把 conformal prediction 从「预测一个量」扩展到「**预留一个资源量**」，是 conformal 保证用于 agent 基础设施决策的范式样例。文中对 agent 系统特征的刻画——「派发时未知、运行时涌现、重尾」——对任何需要给 agent 系统做**容量 / 成本保证**的研究都直接相关；而「分布无关的覆盖保证」与 CARM 的「无分布假设的 O(1/T) 收敛」同属今天这一族工作，可并排阅读。

**链接**
https://arxiv.org/abs/2611.05392

### 8. Understanding the Out-of-Distribution Generalization of Chain-of-Thought Reasoning in LLMs（2611.06438）｜cs.LG stat.ML｜Nuo-Jing Liang, Xiao-Tong Yuan, Pan Zhou

**问题背景**
Chain-of-Thought（CoT）显著提升 LLM 表现，但其**分布外（OOD）泛化机制**在理论上仍欠研究。作者把 CoT 看作**组合式 OOD 泛化**：目标任务缺少完整推理轨迹或直接的输入-输出对，训练只提供分布内（ID）的原子步骤数据。

**方法**
证明 CoT 的泛化方式是**反复应用同一个共享的单步预测器**去组合可复用的 ID 转移。设目标任务的推理步数为 T、每个子任务训练样本数为 n、每步输出 token 数为 k，则给出风险界。

**主要结果**
- **风险界**：OOD 任务风险被 ID 子任务风险之和控制，乘上一个 **O(k)** 量级的系数；该系数**与 T 无关**（但风险总和本身仍随 T 增长）。Rademacher 复杂度分析进一步给出估计项为 **O(√(T/n))** 而非关于 T 的线性——这来自预测器共享 + 共享类上的均匀容量控制。
- **自回归 NTP**：最终任务风险被类内最优步级风险 × 同一 O(k) 系数 + 估计项 **Õ(k√(T/n))** 界定。
- **下界**：parity-coupled 构造表明，当 T ≤ n 时子任务经验风险最小化者的期望最终任务风险至少为类内最优风险 + **Ω(√(T/n))**。
- **实验**（Atom-Task 与 GSM8K）支持该理论：CoT 支持短到长与组合式泛化，且**显式状态跟踪至关重要**。

**与 Reliable Agent · 统计推断的关系**
这是今天唯一给出「**步数 → 风险**」显式界的论文，对「agent 做统计推断时的 bias」有一个具体的量化切入点：**步数越多，累积风险越大**，其增长规律是 **√(T/n)** 而不是 T。作者还指出估计项的 √ 依赖来自「预测器共享」——这提示**多步 agent 若共享同一个推理/估计模块，其误差不会线性累积**，这对设计统计保证是有利的结构性质，值得深挖。

**链接**
https://arxiv.org/abs/2611.06438

### 9. Generalized Hyperrectangular Prediction Sets in Multivariate Conformal Prediction（2611.05543）｜stat.ML cs.LG｜Nabil Alami, Souhaib Ben Taieb

**问题背景与方法**：多元 conformal prediction 中许多非一致性分数产生几何复杂（椭球、密度水平集）且难解释的预测集。论文把它推广为**广义超矩形**（任意一维集合的笛卡尔积），提出 *rectangularization* 框架——把任何连续多元非一致性分数或条件密度转换成产生广义超矩形预测集、并保有**有限样本覆盖**的方法。

**主要结果**：给出该框架的关键几何性质；建立表示定理，证明一大类基于 **max-聚合逐坐标分数**的超矩形 conformal 方法可解释为隐式条件密度的 rectangularization；合成与真实数据实验量化了 rectangularization 的效率代价。

**与用户课题的关系**：这是「牺牲效率换可解释性 + 有限样本覆盖保证」的典型权衡，正是统计保证方向可引用的基线；表示定理也提示超矩形类方法与条件密度估计之间存在结构性联系，可用于讨论「保证强度 vs 几何灵活性」这一核心议题。

**链接**：https://arxiv.org/abs/2611.05543

### 10. Balance-Guided Forest for Causal Effect Estimation（2611.05723）｜stat.ME stat.ML｜Feiyang Yi, Jelena Bradic

**问题背景与方法**：协变量平衡是观测数据因果效应估计的标准做法，难点在于**该平衡哪些特征**。forest-kernel balancing 先学树表示再构造平衡权重，步骤解耦会造成错配（树容量可能浪费在已被充分表示的特征上）。论文提出 **Balance-Guided Forest（BGF）**：用**当前平衡权重**反过来指导后续的树构造，分裂评分同时结合**残余不平衡**与**结果对比**，偏好在不平衡仍存在处分离出与结果相关的区域。

**主要结果**：建立了把该迭代构造与**加权误差、因果偏差**联系起来的 oracle 型界；仿真显示相对既有 forest-kernel 方法在因果估计上有改进；真实数据应用展示了 BGF 在多个观测研究中的实际行为。

**与用户课题的关系**：直接把「**平衡误差 → 因果偏差**」的链条写成了可引用的界，且方法本身是「用当前估计指导下一步搜索」的自适应范式——与 CARM「用成熟反馈在线更新阈值」在结构上同源，可对照阅读。

**链接**：https://arxiv.org/abs/2611.05723

### 11. Cognitive Bias Signatures in Search-Equipped LLM Agents: A Stage-Resolved Analysis（2611.05720）｜cs.CL｜Yanru Xiao, Yingwei Yu

**问题背景与方法**：检索能帮 LLM agent 纠错，但**起始条件**会影响它找到并使用了哪些证据。论文借用认知偏差范式，构造受控检索 harness，在**固定问题与固定文档集**的前提下分别操纵：结果顺序、既往工作的记录、初始假设；用匹配对照把「顺序效应」与「文档组成差异」区分开，把「失败工作记录的影响」与「上下文长度」区分开。

**主要结果**：跨 **10 个模型、1,000 个合成检索世界**，追踪查询、检索文档、文档打开与最终答案。结论：主动检索期间最终答案对**初始证据顺序**的敏感度，高于全部证据一次性给全时；死胡同历史会**降低策略切换**（存在超出上下文长度的效应）；在错误假设下，分阶段测量能区分「检索/打开减少」与「打开反证后错误仍持续」两类失效。探索性干预显示：更频繁地打开反证有时反而伴随**准确率下降**，而准确率也可能在打开量几乎不变时提升。

**与用户课题的关系**：把「agent 的偏差」拆成了**可分阶段定位的认知偏差签名**，方法论上比只报一个总体准确率更有诊断力；「打开反证反而更差」这一反直觉发现，提示检索型 agent 的偏差可能来自**证据消费的停止规则**而非检索能力本身。

**链接**：https://arxiv.org/abs/2611.05720

### 12. Where Search Agents Go Off the Rails: Graph-Grounded Step-Level Verification（2611.06662）｜cs.AI｜Hyeseo Jeon, Seonho Yoo, Jay-Yoon Lee

**问题背景与方法**：检索增强推理系统可以给出正确答案，却在中间步骤出错。可靠审计必须分别检查三件事：证据 D 是否覆盖问题 Q、推理 T 是否回应了 Q、T 是否**扎根于** D。论文提出 **GraphRail**，把需求、证据、推理表示为结构化 claim 并直接比对，**不使用生成式 judge、也不需要标准答案**。

**主要结果**：在三个多跳 QA benchmark × 三个推理框架上，GraphRail 的**错误召回率高于生成式验证器**，且在随机抽取下保持稳定；其诊断结果还能反过来指导在线推理，提供一条可追溯的中间错误检测与纠正路径。

**与用户课题的关系**：直接命中「如何避免用一个有偏的 judge 去评测另一个 agent」这一循环问题——用**结构化 claim 比对**替代生成式评审，是评测环节去 LLM-judge 依赖的一条路；其「提升的是错误召回而非精确率」这一点，在统计上等价于改变**误报-漏报权衡**，与 2611.05662 的结论互补（那边说明 judge 会被带偏，这边说明可以不用 judge）。

**链接**：https://arxiv.org/abs/2611.06662

## 三、几点观察

1. **今天最有价值的不是新方法，是复现与失效机制**。`2611.06307`（risk-control 的复现研究）和 `2611.05650`（agent 失败归因的报告标准）都在做同一件事：**把看起来成立的保证拆开，检查它在什么条件下失效**。这对「Agent 做统计推断时的 bias」这条线可能比再加一个算法更有用——它直接给出该在报告里写什么。
2. **「给 agent 更多工具/证据 ≠ 更可靠」**。`2611.05662` 的 40% 翻转率说明 grounding 不免疫于 confirmation bias；`2611.06662` 则给出绕开 LLM-judge 的替代路线（结构化 claim 比对）。两条合起来指向同一个工程结论：**评测环节要减少对生成式评审的依赖**。
3. **conformal / risk-control 今天出现了三篇不同用法**：`2611.06151`（时序漂移下的自适应风险掩码）、`2611.05392`（用 conformal 预留资源做 agent 编排）、`2611.06307`（复现 conformal 在时序切分下的失效）。第三篇正好是前两篇的必要补丁——读的时候建议连着读。
4. **删失处理值得单独关注**。`2611.05860` 指出「预算耗尽」必须做竞争风险分解而非记为失败，这在评测任何有预算约束的 agent 时都是必须先处理的一步，否则结论有偏。
5. **偏差可以被拆成可定位的签名**。`2611.05720`（检索型 agent 的认知偏差签名）与 `2611.05662`（over-trust / hallucination / under-investigation 三分）都说明：报一个总体指标会掩盖机制差异，而机制差异决定纠正手段。
